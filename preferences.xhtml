Colors AI Chat General Each highlight color has its own configuration. A color left empty is ignored. No color is configured: Annota is inactive. Color Name Optional. Displayed above the fields in the selection popup. 1 Fields Entered when highlighting, in the order of the comment. An empty field is filled by the model when a prompt is set. Types, formats and text syntax Types: text (default), textarea, check, select (comma-separated options), ai (written by the model from the instruction in the options column). Formats: bold, italic, bolditalic, underline, plain (default). Text syntax, one field per line: name | Label | type | options | format. Without options, the format may be given in the fourth column. titre | Titre | text | bold paraphrase | Paraphrase | textarea reference | Référence | text | italic resume | Résumé | ai | Résume le passage en une phrase. | italic The comment has one line per field, in order and in its format. Each field is also a variable ({{name}}) usable in the prompt and the layout. 2 Trigger When the highlight is created On request only (context menu, or when fields are filled in) 3 Prompt optional Without a prompt, the comment is built from the fields alone. With fields, the model fills only the empty ones; entered values are never rewritten. When every field is filled, no request is sent. Custom layout Optional. By default, the comment has one line per field. A layout combines fields, adds fixed text, or inserts {{ai}} for a single free-form answer. Lines whose variables are all empty are removed. Available variables Passage: {{text}}, {{comment}} (existing comment), {{page}}, {{references}} (works cited in the passage). Document: {{title}}, {{authors}}, {{year}}, {{publication}}, {{abstract}}. Settings: {{language}}, {{maxWords}}. Layout only: {{ai}}. These names are reserved for fields. Prompt examples: PROMPT-EXAMPLES.txt in the repository. Reset this color Used by colors that have a prompt, and by the chat. A longer document is reduced to its first page and the pages most relevant to the question. With the PDF open in the reader, page numbers are those printed in the document. Ollama truncates beyond its context window: raise it (OLLAMA_CONTEXT_LENGTH) before increasing the size above.
